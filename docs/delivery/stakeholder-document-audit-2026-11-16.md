Status key:

- **Present:** the named internal function exists in source; acceptance still needs the appropriate tests and release evidence.
- **Partial:** useful source exists, but one or more requested behaviors are absent or differ.
- **Missing:** no complete implementation was found in the reviewed source paths.
- **External gate:** a provider, agreement, regulatory permission, or live acceptance is also required.
- **Conflict:** workbook text differs from an explicit owner rule or approved product decision.

Do not calculate a global completion percentage from cell counts. A cell can contain many independent workflows, and many cells repeat the same shared function.

## Shared evidence that must not be overstated

- `convex/lib/workspaceRoles.ts` grants `operate` to every role except viewer. The type registry explicitly says participant types never grant permissions. A display designation is not a server-enforced task boundary.
- `convex/householdFamily.ts` and `lib/householdFamily.ts` expose only `shared_collection_progress`. Adult confirmation, phone verification, recent authentication, hashed tokens, expiry and revocation are deliberate controls.
- `convex/services.ts` has enquiry/acknowledged/responded/declined/closed states, recipient actions, optimistic versions and history. Every enquiry view states `providerStatus: unavailable`.
- `convex/lib/integrations.ts` exposes `organization:read`, `materials:read`, `inventory:read`, `trades:read`, and `news:read`. This is a bounded read API, not ERP stock posting, purchase-order creation or government filing.
- `convex/stock.ts` returns unknown cost/value as null. Recorded cost is not an independently verified purchase invoice. It values held stock using the current business rate card, not a guaranteed receiving buyer's offer.
- `convex/quality.ts` supports inspection and a specific proposed/approved weight correction. That local maker-checker mechanism is useful evidence, but does not establish dual approval for all deletion, pricing or finance operations.
- `convex/paperDrafts.ts` retains a draft/review boundary. OCR is not automatic stock or cash truth.
- `convex/commercialEvidence.ts`, `schemeClaims.ts`, and `carbonProjects.ts` preserve unverified/reported evidence labels. Do not describe those records as official certificates, financial settlement, or verified legal execution.

## Implementation order

1. **Close permission gaps first.** Distinguish commercial terms, stock entry, quality, dispatch, finance, and team administration at the Convex boundary. Preserve current owners and records. Add denial tests for field staff, stale workspace selection and cross-workspace access. Additive permission changes need an explicit compatibility policy for existing members.
2. **Preserve agreed order terms.** Add and verify a booking price snapshot/acceptance policy before claiming confirmation-time rate locks. Keep reference prices separate. Do not impose a compulsory floor.
3. **Add missing internal registers in bounded slices.** Optional home/day-bag, fleet/dispatch/POD, bay/bale, machine run, scale verification reminders, wet-process logs, programme/campaign attribution and partner catalogues need schemas, permissions, audit trails, UI and tests. Reuse exact grams/paise helpers and private file access.
4. **Define commercial and external contracts.** Set the operating policy for credit/advances, rewards liability/gold, tenders, billing, ERP writes, payroll, welfare records and official filing before enabling execution. Prepare unavailable states and provider adapters without inventing live partners or data.
5. **Accept each external integration separately.** Verify configuration, approved terms/quota, consent, authentic success/failure events, webhook replay protection and real recipient/account results. Do not use one delivered OTP as proof of WhatsApp, payouts, insurer claims or certificate trading.
6. **Release only the verified scope.** Pass the required repository/CI checks, merge the checked PR, deploy the matching Convex backend before the Production frontend, then inspect current public and authorized journeys. List unaccepted provider and device workflows separately for the team.
